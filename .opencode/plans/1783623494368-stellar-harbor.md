# Fix blank Lynx settings pane

## Problem
The Lynx settings tab in Obsidian renders a completely blank pane.

## Root cause
The plugin originally used Obsidian 1.13.0's declarative settings API (`PluginSettingTab.getSettingDefinitions()`). The user's Obsidian version is older than 1.13.0, so that API is unavailable. Obsidian falls back to the imperative `PluginSettingTab.display()` method, which was a generated stub throwing `Method not implemented.`. Earlier attempts to make `display()` a no-op or to keep both APIs caused the pane to remain blank or failed lint.

## Final fix
Switch the settings tab to an imperative `display()` implementation using `obsidian.Setting`, remove `getSettingDefinitions()`, and lower `manifest.json`'s `minAppVersion` to the true API floor of the plugin (`1.7.2`). This makes the settings pane render on the user's current Obsidian while keeping `npm run build` and `npm run lint` clean.

## Files modified
1. `src/settings.ts`
   - Import `App`, `PluginSettingTab`, and `Setting` from `obsidian`.
   - Remove `SettingDefinitionItem`, `getControlValue`, `setControlValue`, and `getSettingDefinitions()`.
   - Implement `display()` with three `Setting` controls that mirror the previous declarative definitions.
2. `manifest.json`
   - Change `minAppVersion` from `1.13.0` to `1.7.2`.
3. `AGENTS.md`
   - Update the `src/settings.ts` description to say the settings tab uses imperative `display()` / `obsidian.Setting`.
   - Update the `minAppVersion` note to explain it is `1.7.2` because of `Workspace.revealLeaf` and other APIs, and that the imperative settings API is intentionally used instead of `getSettingDefinitions()`.

## Verification
- `npm run build` — passes (TypeScript + esbuild).
- `npm run lint` — passes; one warning remains: `obsidianmd/settings-tab/prefer-setting-definitions` because `getSettingDefinitions()` is intentionally omitted. This is a warning, not an error, and is the accepted trade-off for supporting Obsidian versions below 1.13.0.
- Manual test in Obsidian:
  - Copy `main.js`, `manifest.json`, and `styles.css` to `<vault>/.obsidian/plugins/obsidian-lynx/`.
  - Reload Obsidian → Settings → Community plugins → Lynx.
  - Confirm three settings render: Default sort order, Show unresolved links, Open on startup.
  - Confirm each setting can be changed and persists after reload.

## Notes
- If the project later drops support for Obsidian < 1.13.0, switch back to `getSettingDefinitions()` and raise `minAppVersion` to `1.13.0`.
- Do not reintroduce `getSettingDefinitions()` while `minAppVersion` is below `1.13.0`; `eslint-plugin-obsidianmd/no-unsupported-api` will fail the build.
- No changes to `src/main.ts`, `src/links-view.ts`, `src/links-collector.ts`, or `styles.css`.
