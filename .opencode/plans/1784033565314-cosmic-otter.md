# Bidirectional links + line-aware navigation — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Collapse mutual incoming/outgoing notes into one bidirectional row, render with a new icon/color, and jump to the first backlink line on click. Also update `AGENTS.md` so the project notes stay accurate for future agent sessions.

**Architecture:** Extend `LinkType` with `'bidirectional'`, rebuild `collectLinks` around a path-keyed map so each note appears once, store the first backlink `position` for incoming/bidirectional items, and update rendering, sorting, settings, the note picker, and the agent notes to recognize the new type.

**Tech stack:** TypeScript, Obsidian Plugin API, esbuild, ESLint.

## Global constraints

- `minAppVersion` is `1.7.2`; use APIs available in that floor.
- `isDesktopOnly` is `false`; avoid Node/Electron APIs.
- Use sentence case for command names and UI strings.
- Build: `npm run build` (runs `tsc -noEmit -skipLibCheck` then esbuild).
- Lint: `npm run lint` (ESLint flat config from `eslint.config.mts`).
- TypeScript: `strict: true`, `noUncheckedIndexedAccess`, `isolatedModules`, target `ES2021`.
- Do not bundle `obsidian`, codemirror, lezer, or node built-ins.
- Incoming links rely on the undocumented `MetadataCache.getBacklinksForFile`; treat as a breaking-change risk.
- Do not call `detachLeavesOfType` in `onunload`.

- [ ] **Step 2: Replace `collectLinks` body with a path-keyed map**

Implementation outline (exact code to be written):

1. Create `const itemsByPath = new Map<string, LinkItem>()` keyed by `path.toLowerCase()`.
2. If `cache` exists:
   - Iterate `cache.links ?? []` and `cache.frontmatterLinks ?? []`.
   - For each `link`, resolve `dest` via `app.metadataCache.getFirstLinkpathDest(link.link, file.path)`.
   - Determine `path`, `resolved`, `displayName`, `file`, `mtime`.
   - Skip unresolved when `showUnresolved` is false.
   - Store `linkSubpath = extractSubpath(link.link)`.
   - **Do not store `position`** for outgoing links because `ReferenceCache.position` describes the link location in the *source* note, not the target.
   - Insert into `itemsByPath` with `type: 'outgoing'`.
3. If `backlinks?.data` exists:
   - For each `[sourcePath, refs]`:
     - `sourceFile = app.vault.getAbstractFileByPath(sourcePath)`; skip non-`TFile`.
     - Sort `refs` by `position?.start?.line` then `col` ascending.
     - Pick the first ref with a position, otherwise the first ref.
     - Compute `subpath` and `position` from the chosen ref.
     - Lookup key = `sourcePath.toLowerCase()`.
     - If key exists:
       - Set `type = 'bidirectional'`.
       - Set `position` from chosen ref.
       - Keep existing `path`, `file`, `mtime`, `displayName`. If the existing item was unresolved outgoing and the incoming source is resolved, prefer the resolved display name/path when needed.
     - If key missing:
       - Add `type: 'incoming'` with `position` and `linkSubpath: subpath`.
4. Return `Array.from(itemsByPath.values())`.
