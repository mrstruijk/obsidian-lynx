# Plan: Auto-update Lynx panel when settings change

## Goal
When the user changes any display-related Lynx setting, any open Links panel immediately refreshes to reflect the new values.

## Current state
- `src/settings.ts:89-91`, `101-104`, `113-116`, `148-151`, `163-166`, `188-191`, and `224-229` update `plugin.settings` and call `plugin.saveSettings()` but never notify the view.
- `src/links-view.ts:86-95` `update(file)` is the only refresh path; it also pushes to history, which is not desired for a pure settings refresh.
- `src/main.ts:113-119` `updateLinksView(file)` forwards to `view.update(file)`.
- `src/links-view.ts:26` copies `defaultSort` into `currentSort` at construction; `src/links-view.ts:73` sets the dropdown to `currentSort`.

## Implementation steps

1. **Add a lightweight refresh method to the view** (`src/links-view.ts` around line 95, after `update()`).
   - Add `refresh(): void` that:
     - Syncs `currentSort = this.plugin.settings.defaultSort`.
     - Updates `this.sortSelect.value = this.currentSort` if `sortSelect` is initialized.
     - Calls `this.render()` (which already reads `showUnresolved`, colors, and icons from `plugin.settings`).
   - Does **not** modify `currentFile` or history.

2. **Add a plugin-level refresh dispatcher** (`src/main.ts` around line 119, after `updateLinksView()`).
   - Add `refreshAllViews(): void` that iterates `this.app.workspace.getLeavesOfType(VIEW_TYPE)` and calls `leaf.view.refresh()` for any `LynxLinksView` instance.

3. **Wire settings changes to the dispatcher** (`src/settings.ts`).
   - After every `await this.plugin.saveSettings()` in `onChange` callbacks, call `this.plugin.refreshAllViews()`.
   - Affected callbacks:
     - `defaultSort` (`src/settings.ts:89-92`)
     - `showUnresolved` (`src/settings.ts:101-104`)
     - `incomingIcon` (`src/settings.ts:148-151`)
     - `outgoingIcon` (`src/settings.ts:163-166`)
     - `bidirectionalIcon` (`src/settings.ts:188-191`)
     - `addColorSetting` generic callback (`src/settings.ts:224-229`)
   - `openOnStartup` does not affect the panel display; no refresh needed.

4. **Keep existing behavior intact**.
   - The sort dropdown's own `change` listener (`src/links-view.ts:74-79`) continues to update `currentSort`, save the new default, and call `render()`.
   - `updateLinksView()` remains the path for file changes and still pushes history.

## Edge cases covered
- No open panel: `refreshAllViews()` iterates an empty leaf list, no-op.
- Multiple panels: all open `LynxLinksView` instances refresh.
- View not fully initialized: `render()` already guards with `if (!this.listContainer) return`.
- No unwanted history entries: `refresh()` does not touch history.

## Files to modify
- `src/links-view.ts` — add `refresh()` method.
- `src/main.ts` — add `refreshAllViews()` method.
- `src/settings.ts` — call `refreshAllViews()` after each settings `saveSettings()`.
