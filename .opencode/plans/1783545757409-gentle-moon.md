# Lynx: live link refresh

## Goal
Make the Links view refresh when the active note is edited (links added/removed while typing) and when it is saved, while keeping the existing tab-switch behavior.

## Constraints
- Only refresh when the active file changes (confirmed with user).
- Keep existing `file-open` immediate refresh.
- Avoid excessive re-renders while typing.
- No `detachLeavesOfType` in `onunload`.
- Must pass `npm run build` and `npm run lint`.

## Approach
Add two new Obsidian event listeners in `src/main.ts`:

1. `app.metadataCache.on('changed', ...)` — fires when Obsidian re-parses metadata (links, frontmatter) for any file. Filter to the active file and debounce.
2. `app.vault.on('modify', ...)` — fires when a file is saved/modified on disk. Filter to the active file and debounce.

Both route through a plugin-level debounced refresh that always re-reads the current active file, so a pending update cannot stale-update after a tab switch.

`file-open` stays immediate (no debounce) so switching tabs feels instant.

## Files to modify

### `src/main.ts`
- Import `debounce` from `obsidian`.
- Add private field `debouncedUpdateLinksView` using `debounce(() => this.updateLinksView(this.app.workspace.getActiveFile()), 250, true)`.
- In `onload()`, after the existing `file-open` listener, register:
  - `metadataCache.on('changed', (file) => { if (file === this.app.workspace.getActiveFile()) this.debouncedUpdateLinksView(); })`
  - `vault.on('modify', (file) => { if (file instanceof TFile && file === this.app.workspace.getActiveFile()) this.debouncedUpdateLinksView(); })`
- In `onunload()`, call `this.debouncedUpdateLinksView.cancel()`.

No changes needed in `src/links-view.ts`, `src/links-collector.ts`, or `src/settings.ts`.

## Considered alternatives
- **Only `metadata-cache:changed`**: covers typing and save, but user explicitly asked for save behavior too.
- **Only `vault:modify`**: misses live link preview while typing.
- **`editor-change`**: fires on every keystroke even when no link changes; `metadata-cache:changed` is more targeted.
- **Refresh on any file's metadata change**: would keep incoming links live for edits in other notes; user opted out.

## Verification
1. Run `npm run build` — must pass TypeScript and esbuild.
2. Run `npm run lint` — must pass ESLint with obsidianmd rules.
3. Manual test in Obsidian:
   - Open Links view.
   - Switch notes → list updates immediately (existing behavior).
   - In the active note, type `[[New note]]` → link appears after debounce (~250ms pause).
   - Save the active note → list updates (may coalesce with the metadata event).
   - Edit a different note that links to the active note → list does NOT update (per user choice).
