# Plan: show other note's basename/title for every link

## Problem
The previous change removed the path subtitle so modal + sidebar now show one line per link. But the displayed name is not always the title of the *other* note:
- Outgoing links use `link.displayText || link.link`, so aliases or link text can show something other than the target note's basename.
- Incoming links use the first backlink's `displayText` if present, so an alias like `[[Current|Cyclist]]` shows `Cyclist` instead of the source note's basename.

The user wants the label to always be the title (basename) of the *other* note, in both modal and sidebar.

## Root cause
`src/links-collector.ts` sets `LinkItem.displayName`:
- Outgoing: `link.displayText || link.link` (line 52).
- Incoming: `references.find(ref => ref.displayText)?.displayText ?? sourceFile.basename` (lines 76-78).

Both can return alias text rather than the other note's basename.

## Changes
1. `src/links-collector.ts`:
   - Outgoing resolved links: set `displayName` to `dest.basename`.
   - Outgoing unresolved links: derive basename from `link.link` (strip optional `#`/`^` subpath and `.md` extension, take last `/` segment).
   - Incoming links: always set `displayName` to `sourceFile.basename`, ignoring backlink displayText aliases.
2. `src/note-picker-modal.ts` and `src/links-view.ts`: already render only `displayName`; no change needed.
3. `styles.css`: no change needed.

   - Test an outgoing alias (`[[three|alias]]`) and an incoming alias (`[[Current|Cyclist]]`); confirm the label is still the other note's basename, not the alias.
