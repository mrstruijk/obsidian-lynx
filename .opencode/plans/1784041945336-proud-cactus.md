# Plan: display line number after note title in Lynx links panel

## Goal
In the right-sidebar `lynx-links-view`, append the earliest source line number of the reference after each link title: `Note title :12`. Settings let the user enable/disable the number independently for incoming, outgoing, and bidirectional links.

## Changes

### 1. Data layer — `src/links-collector.ts`
- `LinkItem.position` already exists for incoming/bidirectional (`links-collector.ts:30-33`); it records where the reference appears in the *source* note.
- Outgoing items currently discard position info. Update `addOutgoingLinks` (`links-collector.ts:57-81`) so the iteration also captures `position` from `ReferenceCache` for `cache.links` body entries.
- Frontmatter links come as plain `{ link: string }` objects without positions; leave `position` undefined for those.
- When an outgoing item is promoted to bidirectional (`links-collector.ts:110-113`), it already receives the backlink's `position`, which is correct — the line number should now represent where the *other* note references the current note (per user choice).

### 2. Settings — `src/settings.ts`
Add three booleans to `LynxSettings` and `DEFAULT_SETTINGS`:
- `showLineIncoming: true`
- `showLineOutgoing: false`
- `showLineBidirectional: true`

Add three toggle controls in `LynxSettingTab.display()` after the existing icon/color settings, each saving via `saveSettings()` and calling `this.plugin.refreshAllViews()`.

### 3. Rendering — `src/links-view.ts`
In `renderItem` (`links-view.ts:135-177`), after creating the title span:
- Determine if a line number should render based on `item.type` and the matching setting.
- If enabled and `item.position?.start.line` is defined, append a small muted span with class `lynx-link-line` containing ` :${line}`.
- Keep the existing click handlers unchanged.

### 4. Styling — `styles.css`
Add `.lynx-link-line` rule:
- `font-size: var(--font-smallest)` or `var(--font-ui-smaller)`
- `color: var(--text-muted)`
- `margin-left: var(--size-2-1)` (or a tiny gap)
- Avoid growing the row height excessively.

## Verification
1. Run `npm run build` and `npm run lint` in the project root.
2. Manual test in Obsidian:
   - Open a note that has incoming, outgoing, and bidirectional links.
   - Confirm incoming/bidirectional rows show ` :N` after the title by default.
   - Confirm outgoing rows do not show a line number by default.
   - Open Settings → Community plugins → Lynx; toggle each line-number setting and verify the panel refreshes accordingly.
   - Click an incoming/bidirectional link and confirm it still opens the source note and scrolls to the reference position.
3. Edge cases: unresolved outgoing links, frontmatter links, links without position metadata.
